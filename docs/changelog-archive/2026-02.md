### 2026-02-21 — Fix: Next/Submit Button Blocked by Company Applicant (Multi-layer)

**Scope**: `IncomePageNew.svelte`, `Company.svelte`, `home-loan/+page.svelte`, `lap/+page.svelte`, `plot-loan/+page.svelte`, `wizardState.svelte.ts`
**What**: On the Income & Credit step (applicantPageIndex 2), the Submit ("Show Offers") button was disabled when a Company applicant was present alongside Individual applicants. All applicants showed "Done" in the UI but `incomeValueCheck` returned `false`.

**Root cause** (multi-layer):

1. `IncomePageNew.svelte`'s `$effect` completion sync loop evaluated Company applicants with `computeSectionCompletion()` (Individual-only logic), overwriting `__completion: true` → `false`
2. `Company.svelte`'s `submitForm()` set `companyCompletion: true` but never explicitly set `__completion: true` — relied on a reactive `$effect` that could lose the race when the modal unmounted
3. `incomeValueCheck` in all 3 secured loan pages checked only `__completion === true` for ALL applicants, ignoring the `companyCompletion` flag that Company.svelte actually writes on submit
4. `wizardState.svelte.ts` completion map had the same blind spot

**Fix** (4 layers):

1. **IncomePageNew.svelte**: `if (applicant.applicantType === 'Company') continue;` — skips Company in completion sync loop
2. **Company.svelte**: `submitForm()` now explicitly sets `__completion: true` alongside `companyCompletion: true`
3. **home-loan, lap, plot-loan +page.svelte**: `incomeValueCheck` now checks `companyCompletion === true || __completion === true` for Company applicants (belt-and-suspenders)
4. **wizardState.svelte.ts**: Sidebar completion map also recognizes `companyCompletion` for Company type

**Tests**: 4,451 | **Errors**: 0 | **Warnings**: 0
**Course correction**: Initial single-layer fix (IncomePageNew skip) was insufficient — the `__completion` flag had a race condition between Company.svelte unmount and the reactive effect. Made fix comprehensive across all code paths.

**What**: Two bugs found after Phase 1-3 commit:

Also fixed (in Phase 1-3 commit): Admin page Svelte syntax error (`[artifact_id]/test/+page.svelte` — HTML entities in placeholder), YesNoButtons a11y warnings (`<label>` → `<span>`, svelte-ignore for keyboard handler).

**Why tests didn't catch the dropdown bug**: No integration test verifies that every `select`/`derivedSelect` question in the schema has a matching dynamic generator in `optionResolver.ts`. The question-ID-to-generator mapping is a manual contract.
