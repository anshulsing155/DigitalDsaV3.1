### What happened this session (S86) — PMS Phase 5: RM edit mode

Built post-publish revision flow for RMs to edit published policies. Entry A (direct field edit) only; B (delta parse) + Legacy Wins + DSA suggestion chips deferred.

**Server-side (4 additions):**

| File | Change |
|------|--------|
| `policyTypes.ts` | `PolicyDocument.pendingChanges: PendingChange[]` — per-field audit trail |
| `policyService.ts` | `revisePublishedPolicy()` — forks published → new draft; `diffSections()` — per-leaf diff builds PendingChange[]; `patchDraftSections()` — atomic $set + $push + $inc under lock |
| `/api/pms/policies/[id]/revise/+server.ts` | NEW — RM-gated fork endpoint |
| `/api/pms/policies/[id]/+server.ts` | PATCH accepts `rmEdit: true` → routes to patchDraftSections, returns appendedChanges |

**Client-side (13 files):**

| File | Purpose |
|------|---------|
| `edit/+page.server.ts` | Loader — requires active draft; redirects to detail if none; also loads published snapshot for context line |
| `edit/+page.svelte` | Shell — sidebar with 9 sections + unsaved counter + persisted counter; sticky action bar with Save/Submit |
| `edit/_sections/ArrayInput.svelte` | Shared chip-tag input for string arrays |
| `edit/_sections/{9 forms}.svelte` | One per section: Eligibility, Income, FOIR, LTV, Obligations, Tenure, ROI, Geo, Fees |
| `edit/_sections/OtpSubmitModal.svelte` | 6-box OTP modal — reuses encode wizard pattern |
| `[product]/+page.svelte` | Added "Edit policy →" CTA for `status==='published'` |

**Key architectural decisions:**

- **Single page, 9 collapsible section panels** (not 9 routed sub-pages). One state bag, one Save, one Submit. Matches spec mockup.
- **Version on submit, not on save.** Each save PATCHes the same draft and appends PendingChange records; `lockVersion` bumps per save, `version` number only stamps at publish. Per-field PendingChange IS the audit, not a new doc per keystroke.
- **Save-to-draft disabled when clean, Submit-for-approval disabled when dirty OR no persisted changes** — forces the save-then-submit flow.
- **LtvForm handles null state** — unsecured products have `ltv: null`, UI offers explicit Enable/Disable rather than forcing a shape.
- **OTP submit reuses encode wizard pattern exactly** — `computeDraftHash()` fetches live policy and hashes `{sections, overrides}` matching `submit/+server.ts computeDraftHash()`.

**Deferred (tracked):**
- **Entry B (Delta Parse)**: needs new `POST /api/pms/pipeline/delta` + diff-against-existing AI prompt + mini wizard. Own phase-sized effort.
- **Legacy Wins ack flow**: depends on admin-side "legacy comparison" UI which doesn't exist. Only renders if admin creates such a record.
- **DSA suggestion chips (💬)**: `policy_suggestions` collection + submission endpoints don't exist.
