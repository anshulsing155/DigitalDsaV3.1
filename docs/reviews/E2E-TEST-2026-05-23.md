## Payload structure (`POST /api/form/evaluate`)

Captured live (intercepted request body). Fires on **page navigation** (Next/Previous), not per-keystroke (consistent with Pitfall #21). Top-level shape:

```
{
  loanType: string,
  pageIndex: number,
  answers: {
    // derived/computed flags (combinedAnswers-style, "__"-prefixed):
    __allIndividualsNRI, __applicantCount, __hasOnlyNoCurrentIncome,
    __individualApplicantCount, __multiApplicantMode, __onlyCompanyApplicant,
    // real answers, keyed by bindsTo keys:
    assessmentStatus, banksOfCurrentAccount[], businessArea, businessCityName,
    businessEntityType, businessPincode, businessStateName, currentMonth,
    loanAmount, loanName, loanPurpose, loanTenure, loanType,
    selectedIncomeProfiles[], unSecureLoanType, …
  },
  behaviorSignals: {            // anti-scraping telemetry (AD-14), sent every eval
    focusBlurCount, hadFieldFocus, hadKeyboardInput, hadMouseMovement,
    hadPasteEvents, hadScrolling, timeToFirstInteraction
  }
}
```

- ✅ **No PII in the evaluate payload** at the pre-applicant stages observed (no names/PAN/mobile in `answers`; uses bindsTo keys + derived flags). Worth a dedicated check once applicant identity is filled, but the pattern (derived flags + non-PII keys) is consistent with AD-06.
- ℹ️ **`behaviorSignals` rides on every evaluate** — the anti-scraping behavior fingerprint is attached to each server validation call.

## Recurring issue-classes (the "same complaints across sessions")

These showed up **repeatedly across loan types** — fixing the class fixes many instances:

1. 🟠 **Opaque gating (Pitfall #26, everywhere).** Next/Submit/Show-Offers disabled while `Missing: none` and all visible fields filled — the actual blocker is an un-aggregated required radio (HL "registration planned?"), an unattributed "data inconsistency" (PL), or a silent commit gate (income "Add to Profile"). **The aggregate "Missing" hint does not cover all blocking questions, and disabled actions often state no reason.** Single highest-leverage fix.
2. 🟠 **Dropdown option-label collisions.** Any two adjacent bespoke dropdowns sharing an option label (PL "More than 5 years" duration vs experience; HL "Yes" name-on-property vs will-pay-EMI) let a click land on the wrong control. A fast human can mis-set silently. (Also makes the form hard to automate/test.)
3. 🟡 **Result explanations omit the real cause.** PL below-floor → ineligible with every factor green and only "does not meet lender requirements"; the floor gate is invisible to the explanation layer. DSAs can't action what they can't see.
4. 🟡 **Deep progressive reveal with no "you're not done" signal.** Income (salary ~12 fields, business-owner ~10+date) and Deal & Financials (~8 sequential fields) reveal one field at a time; easy to believe you're finished when a later required field hasn't appeared yet.
5. 🟡 **Transition flicker / blank main panel** on step changes (content fades in after a beat; screenshot tooling sees stale frames too).
6. 🟠 **"Previous" rewinds multiple steps / loses in-progress sub-entries.** Form step-Previous is easy to fire unintentionally (ambiguous with in-widget back-nav) and uncommitted sub-form work (an in-progress income entry) is lost on rewind (committed data is retained).
7. 🟢 **Display formatting** — double rupee glyph "+₹₹14.2 L" in result deltas.
